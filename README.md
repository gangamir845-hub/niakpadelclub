# سرور رزرو NIAK Padel Club

این سرور رزروها رو به‌صورت دائمی ذخیره می‌کنه و جلوی رزرو تکراری یک ساعت رو می‌گیره.

## چطور از رزرو تکراری جلوگیری می‌شه

منطق کار روی دو جدول SQLite سوار شده:

| جدول       | نقش                                                                  |
| ---------- | -------------------------------------------------------------------- |
| `bookings` | اطلاعات هر رزرو (تاریخ، زمین، ساعت شروع، مدت، نام، شماره، کد رزرو)   |
| `slots`    | برای هر **ساعت** رزرو‌شده یک ردیف، با کلید یکتا روی `(تاریخ، زمین، ساعت)` |

وقتی کسی رزرو ۲ ساعته از ۱۸:۰۰ ثبت می‌کنه، دو ردیف `18` و `19` در `slots` درج می‌شه. چون کلید
`(date, court, hour)` یکتاست، اگر آن ساعت قبلاً گرفته شده باشه درج شکست می‌خوره و **کل تراکنش
برگشت می‌خوره** و سرور کد `409` برمی‌گردونه.

تراکنش با `BEGIN IMMEDIATE` شروع می‌شه، پس حتی اگر دو نفر در یک لحظه دکمه «ثبت رزرو» رو بزنند،
درخواست‌ها پشت سر هم اجرا می‌شن و فقط یکی موفق می‌شه. تست همزمانی با ۸ درخواست هم‌زمان روی یک
بازه: ۱ موفق (`201`) و ۷ ناموفق (`409`).

نکته مهم: چک کردن خالی بودن ساعت در مرورگر (جاوااسکریپت) فقط برای نمایش است و هیچ‌وقت کافی نیست.
تصمیم نهایی همیشه سمت سرور و داخل همان تراکنش گرفته می‌شه.

## اعلان رزرو جدید

سه راه موازی وجود دارد و هر سه در `notify.py` پیاده شده:

### ۱. ربات تلگرام (فعال)

ربات باشگاه ساخته و وصل شده: **@NiakpadelClub_Bot**. توکن و شناسه چت در `.env` است.
اگر خواستی از صفر ربات تازه بسازی یا توکن را عوض کنی:

1. در تلگرام به [@BotFather](https://t.me/BotFather) پیام بده و `/newbot` را بزن.
   اسم و یک یوزرنیم مختوم به `bot` بده — توکنی مانند
   `7712345678:AAH9x...` می‌گیری.
2. به رباتت وارد شو و یک `/start` بفرست (بدون این کار ربات اجازه پیام دادن ندارد).
3. شناسه چتت را بگیر:

   ```bash
   curl "https://api.telegram.org/bot<TOKEN>/getUpdates"
   # عدد داخل "chat":{"id":123456789,...} همان chat_id توست
   ```

4. سرور را با این دو متغیر اجرا کن:

   ```bash
   export NIAK_TELEGRAM_TOKEN="7712345678:AAH9x..."
   export NIAK_TELEGRAM_CHAT_ID="123456789"
   ```

برای اطلاع چند نفر (مدیر + پذیرش) شناسه‌ها را با کاما بگذار:
`NIAK_TELEGRAM_CHAT_ID="123456789,987654321"`. برای گروه باشگاه، ربات را به گروه
اضافه کن و شناسه منفی گروه (مانند `-1001234567890`) را بگذار.

متن پیامی که می‌رسد:

```
🎾 رزرو جدید ثبت شد

📅 یکشنبه ۲۹ شهریور ۱۴۰۵
🏟 زمین ۱
⏰ ۱۸:۰۰ تا ۲۰:۰۰ (۲ ساعته)
👤 امیر نوری
📞 09121234567
🔖 کد: NIAK-20260920-118
```

### ۲. ایمیل

```bash
export NIAK_SMTP_HOST="smtp.gmail.com"
export NIAK_SMTP_PORT=587
export NIAK_SMTP_USER="you@gmail.com"
export NIAK_SMTP_PASS="app-password"     # گوگل: App Password، نه رمز اصلی
export NIAK_MAIL_TO="you@gmail.com"
```

### ۳. پنل مدیریت زنده

صفحه `admin/` هر ۱۵ ثانیه `/api/admin/latest` را می‌خواند و برای رزرو تازه بوق
می‌زند، اعلان مرورگر می‌دهد و ردیف را با برچسب «جدید» هایلایت می‌کند. هیچ
تنظیمی لازم ندارد.

نکته: ارسال اعلان در پس‌زمینه و **بعد از COMMIT** انجام می‌شود. اگر تلگرام قطع
باشد یا توکن غلط باشد، رزرو با موفقیت ثبت می‌شود و فقط یک خط در لاگ می‌ماند.

اگر پیامک خواستی، کافیست در `notify.py` یک تابع مشابه `_send_telegram` برای API
کاوه‌نگار یا SMS.ir اضافه کنی و در `notify_new_booking` صدایش بزنی.

### دستورهای بات (`bot_commands.py`)

علاوه بر اعلان یک‌طرفه، می‌تونی مستقیم توی چت بات این دستورها رو بزنی:

| دستور | کاربرد |
| --- | --- |
| `/today` | لیست همه‌ی رزروهای امروز |
| `/day <تاریخ>` | رزروهای یک روز دیگر (`/day فردا` یا `/day 2026-09-20`) |
| `/free [تاریخ]` | ساعت‌های خالی هر دو زمین در آن روز |
| `/find <بخشی از شماره>` | جست‌وجوی رزرو بر اساس شماره تلفن (مثال: `/find 0912`) |
| `/move <کد> <تاریخ\|-> <ساعت> [زمین] [مدت]` | جابه‌جایی رزرو (مثال: `/move NIAK-20260920-118 فردا 19 2`) |
| `/cancel <کد رزرو>` | لغو رزرو و آزاد شدن ساعتش (مثال: `/cancel NIAK-20260920-118`) |
| `/help` | راهنما |

`/move` هم مثل ثبت رزرو داخل یک تراکنش `BEGIN IMMEDIATE` کار می‌کند: اول ساعت‌های
قبلی آزاد می‌شوند و بعد ساعت‌های جدید درج می‌شوند. اگر ساعتِ مقصد پر باشد، تراکنش
برمی‌گردد و رزرو قبلی **دست‌نخورده** سر جایش می‌ماند؛ بات هم می‌گوید کدام ساعت‌ها
تداخل داشتند. در `تاریخ` می‌توانی `-` (همان روز)، `امروز`، `فردا` یا `YYYY-MM-DD`
بگذاری؛ `زمین` عدد ۱ یا ۲ و `مدت` ۱ تا ۳ ساعت است. هر دو دستور `/move` و `/cancel`
مستقیم روی همان `data.db` سایت اثر می‌گذارند، پس تغییر بلافاصله در صفحه‌ی رزرو و
پنل مدیریت دیده می‌شود.

این بخش با **long polling** پیاده شده (نیازی به وبهوک و دامنه‌ی HTTPS جدا نداره)
و به‌صورت خودکار همراه `api_server.py` بالا میاد — فایل یا سرویس جدایی لازم نیست.

**فقط چت‌هایی که در `NIAK_TELEGRAM_CHAT_ID` هستن اجازه دارن دستور بدن** — هر پیام از
چت دیگه‌ای (مثلاً اگه یکی گروه رو پیدا کنه یا آیدی بات رو حدس بزنه) کاملاً نادیده
گرفته می‌شه، چون این دستورها نام و شماره تلفن مشتری‌ها رو نشون می‌دن.

اگر می‌خوای این دستورها توی یک **گروه** هم کار کنن (نه فقط چت خصوصی)، باید privacy
mode بات رو غیرفعال کنی: به [@BotFather](https://t.me/BotFather) پیام بده →
`/setprivacy` → ربات رو انتخاب کن → `Disable`. در چت خصوصی نیازی به این کار نیست.

## اجرا

تنظیمات محرمانه در فایل `.env` کنار همین پروژه می‌نشیند. از `.env.example` کپی بگیر:

```bash
pip install fastapi uvicorn
cp .env.example .env      # توکن ربات و رمز پنل را بگذار
chmod 600 .env            # فقط خودت بخوانیش
./run.sh                  # روی پورت 8000 بالا می‌آید
```

`run.sh` خودش `.env` را می‌خواند، پس لازم نیست هر بار متغیرها را دستی export کنی.
فایل `.env` را هرگز در گیت نگذار — در `.gitignore` هست.

## هاست کردن روی سرور خودت

این پروژه دو تکه‌ست که هر دو باید روشن بمونن:

1. **فایل‌های استاتیک سایت** (پوشه‌ی `public/`: HTML/CSS/JS) — هر وب‌سروری (Nginx, Apache, Caddy) سرو می‌کنه.
2. **بک‌اند پایتون** (`api_server.py`) — یه پروسه‌ی همیشه‌روشن که پورت `8000` گوش می‌ده و رزروها/بات تلگرام رو مدیریت می‌کنه.

فرانت‌اند از کجا می‌فهمه بک‌اند کجاست؟ فقط از یه جا: **`assets/config.js`**. توی همه‌ی
صفحات این فایل قبل از بقیه‌ی اسکریپت‌ها لود می‌شه و مقدار `window.NIAK_API_BASE`
رو ست می‌کنه. برای هاست خودت لازم نیست هیچ فایل HTML‌ای رو دستی ویرایش کنی — فقط
همین یه فایل.

### روش توصیه‌شده: یک دامنه با Nginx (بدون دردسر CORS)

بک‌اند رو پشت همون دامنه‌ی سایت، روی مسیر `/api/`، پروکسی کن. توی این حالت
`assets/config.js` نیازی به تغییر نداره (مقدار پیش‌فرضش `''` یعنی «همون دامنه»).

```bash
# ۱. پروژه رو روی سرور بذار (مثلاً /opt/niak برای بک‌اند و /var/www/niak-padel-club برای فرانت)
cp .env.example .env && nano .env      # توکن‌ها و رمز پنل رو بگذار
pip install fastapi uvicorn

# ۲. بک‌اند رو با systemd همیشه روشن نگه دار
sudo cp deploy/niak-api.service.example /etc/systemd/system/niak-api.service
sudo nano /etc/systemd/system/niak-api.service   # مسیرها رو با مسیر واقعی خودت تطبیق بده
sudo systemctl daemon-reload
sudo systemctl enable --now niak-api

# ۳. Nginx رو برای سرو فرانت + پروکسی /api/ تنظیم کن
sudo cp deploy/nginx.conf.example /etc/nginx/sites-available/niak-padel
sudo nano /etc/nginx/sites-available/niak-padel  # دامنه و مسیر ریشه رو عوض کن
sudo ln -s /etc/nginx/sites-available/niak-padel /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

# ۴. گواهی SSL رایگان (پیشنهاد می‌شه، نه اجباری)
sudo certbot --nginx -d niakpadel.ir -d www.niakpadel.ir
```

نمونه‌های آماده‌ی هر دو فایل توی پوشه‌ی `deploy/` هست — فقط دامنه، مسیرها و
یوزر سیستم رو با مقادیر واقعی سرور خودت جایگزین کن.

### روش جایگزین: بک‌اند روی پورت/دامنه‌ی جدا

اگه نمی‌خوای از Nginx reverse proxy استفاده کنی (مثلاً بک‌اند رو مستقیم روی
پورت 8000 باز گذاشتی، یا روی یه ساب‌دامین جدا مثل `api.niakpadel.ir` سرو
می‌کنی)، توی `assets/config.js` آدرس کامل بک‌اند رو بذار:

```js
window.NIAK_API_BASE = 'https://api.niakpadel.ir';
// یا: window.NIAK_API_BASE = 'https://niakpadel.ir:8000';
```

توی این حالت، چون فرانت و بک‌اند روی دو origin جدا هستن، باید دامنه‌ی سایت رو
هم به `.env` اضافه کنی وگرنه مرورگر درخواست‌ها رو به‌خاطر CORS رد می‌کنه:

```bash
NIAK_ALLOWED_ORIGINS=https://niakpadel.ir,https://www.niakpadel.ir
```

### چک کردن نهایی

بعد از بالا اومدن همه‌چی:

```bash
curl https://niakpadel.ir/api/health
# باید چیزی شبیه {"ok":true,"notifications":{...}} برگردونه
```

اگه این جواب نداد، اول `systemctl status niak-api` و `journalctl -u niak-api -f`
رو چک کن (بک‌اند بالا نیومده؟)، بعد `sudo nginx -t` (خطای کانفیگ؟).

برای اجرای دائمی روی سرور واقعی (خلاصه، جزئیاتش بالاست):

```bash
# نمونه systemd
[Service]
WorkingDirectory=/opt/niak
EnvironmentFile=/opt/niak/.env
ExecStart=/opt/niak/run.sh
Restart=always
```

## آدرس‌ها

| متد     | آدرس                              | توضیح                                             |
| ------- | --------------------------------- | ------------------------------------------------- |
| GET     | `/api/bookings?date=YYYY-MM-DD`   | ساعت‌های پرِ هر زمین (بدون اطلاعات شخصی)          |
| POST    | `/api/bookings`                   | ثبت رزرو — `201` موفق، `409` تداخل، `400` نامعتبر |
| GET     | `/api/mybookings?phone=…`         | رزروهای مشتری با شماره تلفن (صفحه‌ی «رزروهای من») |
| DELETE  | `/api/mybookings/{code}?phone=…`  | لغو خودِ مشتری — به شماره تلفن **و** کد رزرو نیاز داره |
| GET     | `/api/admin/bookings?token=…`     | لیست کامل رزروها با نام و شماره                   |
| GET     | `/api/admin/latest?token=…&since_id=N` | تعداد رزروهای تازه — برای هشدار پنل          |
| DELETE  | `/api/admin/bookings/{id}?token=…`| لغو رزرو و آزاد شدن ساعت‌هایش                     |

بدنه POST:

```json
{ "date": "2026-09-20", "court": 0, "start": 18, "duration": 2,
  "name": "نام مشتری", "phone": "09120000000" }
```

### صفحه‌ی «رزروهای من» (`mybookings/`)

مشتری بدون هیچ حساب کاربری‌ای، فقط با وارد کردن شماره تلفنی که موقع رزرو داده،
لیست رزروهاش رو می‌بینه و می‌تونه لغوشون کنه. چند نکته درباره‌ی طراحی امنیتیش:

- **دیدن لیست** فقط با شماره تلفن انجام می‌شه — یعنی هرکس شماره تلفن یه نفر
  دیگه رو بدونه، می‌تونه رزروهای اونو هم ببینه (مثل خیلی از سیستم‌های ساده‌ی
  «پیگیری سفارش با شماره تلفن»). برای این پروژه (باشگاه محلی، بدون اطلاعات
  حساس مثل شماره کارت) این ریسک قابل قبول در نظر گرفته شده، ولی اگه بعداً
  خواستی سخت‌گیرانه‌تر بشه، راه‌حلش اضافه کردن تأیید با پیامک (OTP) هست.
- **لغو کردن** سخت‌گیرانه‌تره: هم شماره تلفن هم کد رزرو (همونی که موقع ثبت
  رزرو نمایش داده می‌شه) با هم لازمه — پس صرفِ دونستن شماره تلفن یه نفر برای
  لغو کردن رزروش کافی نیست.
- هر دو مسیر جداگانه و سخت‌گیرانه‌تر از ثبت رزرو محدود شدن (rate limit) تا
  کسی نتونه شماره‌ها رو پشت سر هم امتحان کنه.

## پشتیبان‌گیری

کل داده در فایل `data.db` است. یک cron روزانه کافیست:

```bash
sqlite3 /opt/niak/data.db ".backup /opt/niak/backup/$(date +%F).db"
```

## اگر نخواستی سرور بزنی

همین ساختار جدول را می‌تونی روی Supabase یا هر Postgres دیگری پیاده کنی:

```sql
CREATE TABLE slots (
  date date NOT NULL, court int NOT NULL, hour int NOT NULL,
  booking_id bigint REFERENCES bookings(id) ON DELETE CASCADE,
  PRIMARY KEY (date, court, hour)
);
```

قید `PRIMARY KEY` همان نقش قفل را بازی می‌کند. درج تمام ساعت‌های یک رزرو باید داخل یک تراکنش
انجام شود تا رزرو تکراری غیرممکن بماند.
